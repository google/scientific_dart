## 0.1.0-wip

- **Breaking — Typed Second Operand & `SelfOf` Bounds on Same-DType Functions**:
  - The top-level element-wise binary functions (`add`, `subtract`, `multiply`, `divide`, `floorDivide`, `pow`, `power`, `remainder`, `mod`, `fmod`, `maximum`, `minimum`, `atan2`, `hypot`, `copysign`, `gcd`, `lcm`, `bitwiseAnd`, `bitwiseOr`, `bitwiseXor`, `leftShift`, `rightShift`) and the comparison functions (`equal`, `notEqual`, `greater`, `greaterEqual`, `less`, `lessEqual`) now take a `GpuArray<T>` second operand instead of `Object?`. Scalars remain available through the instance methods and operators (`a.add(2.0)`, `a + 2.0`, `a.equal(0)`, `a.leftShift(1)`); `add(a, 2.0)` no longer compiles.
  - Every function whose type parameter binds two or more input arrays is bounded by `SelfOf<...>`, mirroring `package:ndarray` 0.3.0: `T extends SelfOf<DTypeTag>` for the dtype-preserving arithmetic, comparison, tensor (`matmul`, `dot`, `vdot`, `multiDot`, `einsum`, `tensordot`, `kron`, `inner`, `outer`, `cross`) and neural-network (`mseLoss`, `l1Loss`, `binaryCrossEntropy`, `scaledDotProductAttention`, and the `MSELoss` / `L1Loss` / `BCELoss` criteria) functions; `T extends SelfOf<DivideOf<R>>` for `divide`; `T extends SelfOf<RealOf<BitwiseDType>>` for `bitwiseAnd` / `bitwiseOr` / `bitwiseXor`; and `T extends SelfOf<RealOf<IntegerDType>>` for `leftShift` / `rightShift` / `gcd` / `lcm`. Because every concrete tag implements `SelfOf` while the least upper bounds of distinct tags (`DTypeTag`, `BitwiseDType`, `IntegerDType`) do not, mixed-dtype calls such as `add(f64, f32)`, `add(i64, i32)`, `matmul(f64, f32)`, `bitwiseAnd(i64, i32)`, `multiDot([f64, f32])` and mismatched output buffers such as `add(f64, f64, out: f32)` are rejected at compile time, while same-dtype calls still infer `T` without type arguments.
  - The unary `bitwiseNot` / `invert` functions are bounded by `T extends RealOf<BitwiseDType>`, so floating-point and complex arrays (and `GpuArray<AnySpec>`) are rejected at compile time.
  - `atan2`, `hypot` and `copysign` keep the input dtype at run time (integer inputs are computed in floating point and cast back), so they use `SelfOf<DTypeTag>` rather than a promoting projection. `ldexp` is the one genuinely mixed-dtype binary function: the exponent is converted to a 32-bit integer on the device after promotion, so it is typed `ldexp<T extends DTypeTag>(GpuArray<T> a, GpuArray<DTypeTag> b)` and keeps the mantissa dtype.
  - The run-time semantics of the instance methods and operators are unchanged: mixed-dtype operands are still promoted and cast back to the receiver's dtype, and the accumulating reductions `sum` / `nansum` / `prod` keep `T extends DTypeTag` because their `dtype:` parameter deliberately requests a different result dtype.

- **Breaking — Marker-Bounded Bitwise & Shift Operators**:
  - The `&`, `|`, `^`, `~` operators moved from the `GpuArray` class to `extension GpuArrayBitwise<T extends BitwiseDType> on GpuArray<T>`, and `<<`, `>>` to `extension GpuArrayShift<T extends IntegerDType> on GpuArray<T>`. They are therefore only available on integer and boolean tags and on their least upper bounds (`GpuArray<IntegerDType>`, `GpuArray<BitwiseDType>`); `f32 & f32`, `~f64`, `b << 1` and `GpuArray<DTypeTag>` receivers are compile-time errors (`undefined_operator`).
  - The non-generic siblings `GpuArrayBitwiseSpec on GpuArray<AnyBitwiseSpec>` and `GpuArrayShiftSpec on GpuArray<AnyIntegerSpec>` provide the same operators for the run-time-checked rows returned by the new escape hatches.

- **Escape Hatches (`asAnySpec`, `asBitwiseDType`, `asIntegerDType`)**:
  - `GpuArray.asAnySpec` views any array as `GpuArray<AnySpec>` (a zero-allocation cast) so it satisfies every `SelfOf<...>` and projection bound with run-time dtype validation. `GpuArray.asBitwiseDType` returns `GpuArray<AnyBitwiseSpec>` and `GpuArray.asIntegerDType` returns `GpuArray<AnyIntegerSpec>` after checking the run-time dtype (an `ArgumentError` otherwise), so dynamically typed integer / boolean arrays can call the bitwise and shift functions and operators.
  - `SelfOf`, `AnyBitwiseSpec`, `AnyIntegerSpec`, `InexactSpec`, `DivideSpec` and `DoublePrecisionSpec` are now re-exported from `package:gpuarray/gpuarray.dart` so generic helpers can spell these bounds without importing `package:ndarray`.

- **Run-Time-Determined Result DTypes Default to `AnySpec`**:
  - `where`, `select`, `concatenate`, `stack`, `vstack`, `hstack`, `dstack`, `columnStack`, `permutation` (function and `GpuRandom` method), and `CompiledWgslKernel.run` / `execute` / `executePositional` / `call` / `WgslJitCompiler.execute` type their result only through an optional `out:` (their inputs are promoted at run time). Their result type parameter is now bounded by `AnySpec` instead of `DTypeTag`, so without `out:` the result is `GpuArray<AnySpec>` and composes with every other operation (`add(concatenate([a, b]), c)`) under run-time dtype validation, while `out: GpuArray<Float32>` still infers `GpuArray<Float32>`. A bare `GpuArray<DTypeTag>` can no longer be passed as that `out:` (widen with `.asAnySpec`).

- **Breaking — `out:` Buffers Are Checked at Compile Time (`Out extends T`)**:
  - Every function whose `out:` dtype must equal an input's dtype or a projection of it now types that buffer by a dependent type parameter declared last: `sort<T extends DTypeTag, Out extends T>(GpuArray<T> a, {GpuArray<Out>? out})`, `sin<T extends DTypeTag, Out extends T>(GpuArray<T> a, {GpuArray<Out>? out})`, `divide<T extends SelfOf<DivideOf<R>>, R extends DTypeTag, Out extends R>`, `sumAs<R extends DTypeTag, Out extends R>`, `topk<T extends DTypeTag, OutValues extends T>`, `eigh<T, F, OutEigenvalues extends F, OutEigenvectors extends T>`, `svd<T, F, OutU extends T, OutS extends F, OutVt extends T>`, and so on across all `out:`-bearing operations. Previously `sort(f64, out: f32)` inferred `T = DTypeTag` and failed at run time; it is now a compile-time `could_not_infer` error, while `sort(f64)`, `sort(f64, out: f64)`, `sort(dyn)` and `T extends DTypeTag` generic callers are unchanged. Return types are unchanged (`GpuArray<T>` / `GpuArray<R>`). The same-dtype binary functions (`add`, `matmul`, ...) did not need this: their `SelfOf`-bounded `T` already rejects a mismatched `out:`.
  - Methods whose output dtype is chosen only by an optional `dtype:` and/or `out:` — `CompiledWgslKernel.run` / `execute` / `executePositional` / `call` and `WgslJitCompiler.execute` — are bounded by `T extends AnySpec` with `dtype: DType<T>?` and `out: GpuArray<T>?`, so `dtype: DType.float32` or `out: f32` alone infers `GpuArray<Float32>`, `execute(expr, inputs, dtype: DType.float64, out: f32)` is rejected, and the default result is `GpuArray<AnySpec>`.
  - Re-exported `DType.asAnySpec` from `package:ndarray` for passing a run-time-chosen dtype to `AnySpec`-bounded parameters.

- **Migration Guide**:
  - **Explicit type arguments on `out:`-bearing functions**: `sin<Float32>(x)`, `sumAs<Int64>(a, DType.int64)`, `topk<Float32>(a, 2)` no longer match the parameter count. Drop them — inference produces the same types — or add the new trailing parameter(s).
  - **`out:` buffers must match statically**: create the buffer with the concrete dtype of the input (`GpuArray.zeros(shape, DType.float32)` for a `Float32` input), or, when the dtype is only known at run time, widen both the input and the buffer with `.asAnySpec` so the dtype is validated at run time as before. A `GpuArray<DTypeTag>` input still accepts any `out:` (`sort(dyn, out: f32)`).
  - **Optional `dtype:` with a run-time dtype**: pass `dtype: dt.asAnySpec` (or declare dtype lists as `<DType<AnySpec>>[...]`) when calling `CompiledWgslKernel` / `WgslJitCompiler` with a run-time `DType<DTypeTag>`.
  - **Scalars in top-level binary functions**: replace `add(a, 2.0)`, `maximum(a, 10.0)`, `pow(a, 2.0)`, `leftShift(a, 1)`, `equal(a, 0)` with the method or operator form: `a.add(2.0)` / `a + 2.0`, `a.maximum(10.0)`, `a.pow(2.0)`, `a.leftShift(1)` / `a << 1`, `a.equal(0)`.
  - **Run-time-typed arrays**: a `GpuArray<DTypeTag>` (for example the result of `Module.forward` on an untyped input, or of `mean` / `cumsum` / `bincount`) passed to a `SelfOf`-bounded function must be widened with `.asAnySpec` (`scaledDotProductAttention(x.asAnySpec, x.asAnySpec, x.asAnySpec)`), or with `.asBitwiseDType` / `.asIntegerDType` for the bitwise and shift families; the result is then `GpuArray<AnySpec>` (or the corresponding row) and the dtype is validated at run time.
  - **Generic helpers**: a helper that forwards two arrays of one type parameter `T` to `add`, `matmul`, `gcd`, `mseLoss`, ... must declare the same kind of bound (`T extends SelfOf<DTypeTag>`, `T extends SelfOf<RealOf<IntegerDType>>`, ...); `T extends DTypeTag`, `T extends BitwiseDType` and `T extends IntegerDType` no longer compile for those calls. If the helper must keep `T extends DTypeTag` (for example an override of `Module.forward`), widen the arguments with `.asAnySpec` and cast the result back `as GpuArray<T>`. If the helper also needs a projecting operation on the same `T`, bound it by a row (`AnySpec`, `DivideSpec<R>`, `AnyBitwiseSpec`, `AnyIntegerSpec`) instead.
  - **Bitwise operators on widened receivers**: `GpuArray<DTypeTag>` and `GpuArray<AnySpec>` receivers no longer have `&`, `|`, `^`, `~`, `<<`, `>>`; use `.asBitwiseDType` / `.asIntegerDType` first, or the methods (`a.bitwiseAnd(b)`), which remain available on every dtype.
  - **Explicit `concatenate<T>` / `where<T>` type arguments** inside code generic over `T extends DTypeTag` must drop the type argument and cast the `GpuArray<AnySpec>` result (`concatenate(parts) as GpuArray<T>`).
